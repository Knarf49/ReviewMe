# Postgres chat schema + Docker dev stack

**Date:** 2026-05-21
**Status:** Draft — pending user review
**Scope:** Add persistent chat history storage to ReviewMe. Establish Postgres + Alembic + pgAdmin dev stack. No app-level integration in this PR (separate phase).

## Goal

Add a Postgres database to ReviewMe with three tables (`users`, `threads`, `messages`) for storing chat conversations. Provide a one-command developer setup via `docker compose` with pgAdmin for inspection. Schema lifecycle managed by Alembic with SQLAlchemy models as the canonical source.

## Non-goals

- Wiring chat persistence into `app.py` / Gradio (deferred to follow-up phase)
- Authentication / login flow (`role` column reserved for future)
- Redis / worker queue (deferred to worker phase)
- Production deployment, secrets management beyond `.env`, CI integration
- Data migration from any existing storage (none exists)

## Architecture

```
┌─────────────────────────────────────────────────────────┐
│ Host: docker compose                                    │
│                                                         │
│  ┌──────────────────┐         ┌──────────────────┐      │
│  │ postgres:16      │◄────────│ pgadmin:8        │      │
│  │ port 5432        │  net    │ port 5050        │      │
│  │ vol: pgdata      │         │ vol: pgadmin_data│      │
│  └────────▲─────────┘         └──────────────────┘      │
│           │                                             │
└───────────┼─────────────────────────────────────────────┘
            │ DATABASE_URL=postgresql+psycopg://...
            │
   ┌────────┴─────────┐
   │ app/ (host)      │
   │  core/db.py      │  ← engine, Session factory
   │  core/models.py  │  ← SQLAlchemy declarative models
   │  alembic/        │  ← versioned migrations
   └──────────────────┘
```

Two containers (`postgres`, `pgadmin`) on a shared compose network. App stays on host (Gradio dev workflow unchanged). Alembic = schema lifecycle. SQLAlchemy 2.0 declarative models = canonical source; initial migration generated by `alembic revision --autogenerate` then hand-tuned for CHECK constraints and indexes.

## Components

### Containers (`docker-compose.yml` at repo root)

- `postgres:16-alpine`
  - Port `5432:5432`
  - Volume `pgdata:/var/lib/postgresql/data`
  - Env: `POSTGRES_USER`, `POSTGRES_PASSWORD`, `POSTGRES_DB`
  - Healthcheck: `pg_isready -U $POSTGRES_USER` interval 5s retries 5
  - `restart: unless-stopped`

- `dpage/pgadmin4:8`
  - Port `5050:80`
  - Volume `pgadmin_data:/var/lib/pgadmin`
  - Env: `PGADMIN_DEFAULT_EMAIL`, `PGADMIN_DEFAULT_PASSWORD`
  - Mount `./db/pgadmin/servers.json:/pgadmin4/servers.json:ro` for auto-register
  - `depends_on: postgres: { condition: service_healthy }`
  - `restart: unless-stopped`

## Schema

### Tables

```sql
users
  id            SERIAL       PRIMARY KEY
  username      VARCHAR(64)  NOT NULL UNIQUE
  email         VARCHAR(254) NOT NULL UNIQUE
  password_hash VARCHAR(255) NOT NULL                      -- bcrypt / argon2 only
  role          VARCHAR(32)  NOT NULL DEFAULT 'user'
  created_at    TIMESTAMPTZ  NOT NULL DEFAULT now()

threads
  id            SERIAL       PRIMARY KEY
  user_id       INTEGER      NOT NULL REFERENCES users(id) ON DELETE CASCADE
  created_at    TIMESTAMPTZ  NOT NULL DEFAULT now()

messages
  id            SERIAL       PRIMARY KEY
  thread_id     INTEGER      NOT NULL REFERENCES threads(id) ON DELETE CASCADE
  role          VARCHAR(16)  NOT NULL CHECK (role IN ('user','assistant','system'))
  content       TEXT         NOT NULL
  created_at    TIMESTAMPTZ  NOT NULL DEFAULT now()
```

### Indexes

- `idx_threads_user_id` on `threads(user_id)` — list threads per user
- `idx_messages_thread_created` on `messages(thread_id, created_at)` — fetch thread chronologically

### Deviations from raw spec (all explicitly approved by user)

| Raw spec field            | Implemented as                  | Reason                                                |
|---------------------------|---------------------------------|-------------------------------------------------------|
| `Table users` (lowercase) | `users`                         | PG convention; no double-quoting                      |
| `Table Thread`            | `threads` (lowercase, plural)   | PG convention; consistent with `users`                |
| `Table Message`           | `messages` (lowercase, plural)  | PG convention; consistent with `users`                |
| `password varchar`        | `password_hash VARCHAR(255)`    | Documents intent; app stores bcrypt/argon2 only       |
| `created_at timestamp`    | `TIMESTAMPTZ`                   | Timezone-aware (PG best practice)                     |
| `Content string`          | `content TEXT`                  | No length cap for messages                            |
| `varchar` (unbounded)     | bounded `VARCHAR(n)`            | Reasonable upper bounds; CHECK on `messages.role`     |
| FK relations              | `ON DELETE CASCADE`             | Chat history owned by user; clean removal             |

`messages.role` is kept as `VARCHAR(16)` + CHECK rather than a Postgres ENUM type so that migrations stay simple (adding a value to an ENUM requires DDL).

## Error handling

**Compose / containers:**

- `restart: unless-stopped` on both services
- Postgres healthcheck (`pg_isready`) gates pgAdmin startup via `depends_on`
- Named volumes persist data across container recreate

**Alembic:**

- `env.py` reads `DATABASE_URL` from environment (with `.env` fallback via `python-dotenv`)
- Missing `DATABASE_URL` → `RuntimeError` with the explicit fix message
- Each migration runs inside a transaction (Alembic default for Postgres)

**App connection (`app/core/db.py`):**

- Engine constructed at module import; psycopg only connects on first use (lazy)
- `pool_pre_ping=True` reconnects stale pooled connections
- `get_db()` context manager: commit on success, rollback on exception, close always
- DB unreachable → `OperationalError` bubbles to caller

**Boundaries:**

- App import never fails if DB down
- Migration failure halts cleanly (transactional) — no partial schema
- pgAdmin failure is non-fatal for the app

## Testing

### Strategy

- Tests hit a real Postgres database `reviewme_test` on the same compose container (per user feedback rule — no DB mocks)
- Schema for tests created via `Base.metadata.create_all()` for speed (not Alembic)
- Per-test isolation via SAVEPOINT rollback fixture

### Files

```
tests/
  conftest.py            # engine, session, transactional fixture
  test_models.py         # FK cascade, CHECK constraints, defaults, uniqueness
  test_migrations.py     # alembic upgrade head → downgrade base round-trip
```

### What gets tested

- Round-trip: create `User` → `Thread` → `Message`
- `ON DELETE CASCADE`: deleting user wipes threads + messages
- CHECK constraint: `messages.role NOT IN ('user','assistant','system')` raises `IntegrityError`
- Uniqueness: duplicate `username` / `email` raises `IntegrityError`
- Defaults: `created_at` populated, `users.role` defaults to `'user'`
- Alembic round-trip: `upgrade head` → `downgrade base` returns to empty schema

### Out of scope for tests

- pgAdmin UI (manual)
- `docker compose up` end-to-end (verified manually per README)
- Connection-pool behavior
- CI workflow (no CI changes in this PR)

## Acceptance criteria

1. `docker compose up -d` brings up Postgres (healthy) + pgAdmin without manual intervention
2. Browsing `http://localhost:5050` shows the `reviewme` server already registered
3. `alembic upgrade head` creates all three tables with constraints + indexes
4. `pytest tests/test_models.py tests/test_migrations.py` passes against the running container
5. `alembic downgrade base` removes the schema cleanly
6. README documents the full bring-up sequence
